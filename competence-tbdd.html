L'ORGANISATION DES DONNÉES

Les Bases de Données dans la vie courante

Imaginez une bibliothèque. Si tous les livres étaient jetés en vrac sur le sol, il serait impossible de trouver un ouvrage spécifique. Pour résoudre ce problème, la bibliothèque utilise un système de classement (par genre, par auteur, par titre).

De la même manière, une Base de Données est un système organisé qui permet de stocker, de gérer et de retrouver rapidement des informations. Que ce soit pour une banque, un site de e-commerce, ou un réseau social, tout repose sur une base de données bien conçue.

Les Clés (PK & FK)

Les clés primaires (PK) identifient de manière unique chaque enregistrement. Les clés étrangères (FK) relient les tables entre elles, assurant la cohérence des données.

Normalisation

Le processus qui consiste à organiser les données pour réduire la redondance et éviter les anomalies d'insertion, de suppression ou de mise à jour.

Transactions & Sécurité

Garantir que les opérations sur la base sont atomiques (tout ou rien). Gestion des droits d'accès et des sauvegardes pour protéger les données.

Les fondamentaux des Bases de Données

Des schémas relationnels aux requêtes complexes, voici les clés d'une base de données performante.

1. Le Modèle Relationnel (Le dessin de la DB)

Le modèle relationnel organise les données sous forme de tables (relations) composées de colonnes (champs) et de lignes (enregistrements).

2. Requêtes SQL Avancées (Explications détaillées)

Au-delà du SELECT basique, nous avons appris à interroger plusieurs tables simultanément.

Le JOIN (Liaison entre tables) :
SELECT Livre.titre, Auteur.nom
FROM Livre
JOIN Auteur ON Livre.id_auteur = Auteur.id_auteur;
➜ Récupère le titre du livre et le nom de l'auteur en reliant les deux tables via la clé étrangère.
Le GROUP BY et les Agrégats :
SELECT Auteur.nom, COUNT(Livre.id_livre) as nombre_livres
FROM Auteur
JOIN Livre ON Auteur.id_auteur = Livre.id_auteur
GROUP BY Auteur.nom;
➜ Compte le nombre de livres écrits par chaque auteur et regroupe les résultats par nom d'auteur.

3. La Normalisation (1FN, 2FN, 3FN)

La normalisation est un processus qui permet de structurer les données pour éliminer les redondances et garantir l'intégrité.

  • 1ère Forme Normale (1FN) : Chaque colonne contient une valeur atomique (indivisible).
  • 2ème Forme Normale (2FN) : La table est en 1FN et tous les attributs dépendent de la clé primaire entière.
  • 3ème Forme Normale (3FN) : La table est en 2FN et il n'y a pas de dépendance transitive (un attribut ne dépend pas d'un autre attribut non-clé).
